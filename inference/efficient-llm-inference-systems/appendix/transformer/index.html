Transformer

LLM 추론 파이프라인

Section titled “LLM 추론 파이프라인”

LLM은 문장을 한 번에 완성하지 않는다. 입력 문맥을 기반으로 다음 토큰 하나의 확률 분포를 계산하고, 그중 하나를 선택한 뒤, 선택된 토큰을 다시 문맥에 붙여 반복 생성한다.

Autoregressive generation은 전체 문장 확률을 각 시점의 다음 토큰 확률의 곱으로 표현한다.

P(x1,x2,...,xT)=∏t=1TP(xt∣x<t)P(x_1, x_2, ..., x_T) = \prod_{t=1}^{T} P(x_t \mid x_{\lt t}) P(x1​,x2​,...,xT​)=t=1∏T​P(xt​∣x<t​)

Decoder-only LLM의 전체 추론 흐름은 다음과 같다.

Decoder Self-Attention Flow

Section titled “Decoder Self-Attention Flow”

위 그림은 decoder-only self-attention이 입력 토큰을 문맥화된 표현으로 바꾸는 과정을 요약한다.

  1. 입력 문자열을 토큰 ID로 변환하고 token embedding을 lookup한다.
  2. 위치 정보를 더하거나 RoPE처럼 Q, K에 위치 정보를 주입한다.
  3. 입력 embedding에서 Q, K, V를 linear projection으로 만든다.
  4. QK^T로 attention score를 계산한다.
  5. causal mask를 적용해 각 토큰이 미래 토큰을 보지 못하게 한다.
  6. sqrt(d_k)로 scaling하고 softmax로 attention probability를 만든다.
  7. attention probability와 V를 곱해 value의 weighted sum을 만든다.
  8. multi-head attention 출력을 residual connection, LayerNorm, MLP/FFN과 함께 Transformer block 안에서 처리한다.

Tokenization

Section titled “Tokenization”

LLM은 문자열을 직접 처리하지 않고, 먼저 텍스트를 토큰 단위로 나눈다. 이 appendix의 그림과 이어지는 self-attention 예시는 "hello"가 ["_hel", "lo"] 두 토큰으로 나뉜다고 가정한다.

위 token ID는 shape 설명을 위한 예시값이다. 실제 토큰 분할과 ID는 사용하는 tokenizer와 vocabulary에 따라 달라진다.

Vocabulary size를 V라고 하면 각 token ID는 보통 다음 범위 안에 있다.

0≤token_id<V0 \leq token\_id < V 0≤token_id<V

예를 들어 vocabulary size는 모델에 따라 32,000, 50,257, 128,000처럼 달라질 수 있다.

Embedding Lookup

Section titled “Embedding Lookup”

Token ID는 정수일 뿐이므로 모델이 계산할 수 있는 dense vector로 바꿔야 한다. 이를 위해 embedding matrix를 사용한다.

E∈RV×dmodelE \in \mathbb{R}^{V \times d_{model}} E∈RV×dmodel​

토큰 ID x_i에 대한 embedding vector는 embedding matrix의 해당 row를 lookup해서 얻는다.

ei=E[xi]e_i = E[x_i] ei​=E[xi​]

입력 토큰 수가 n개이면 embedding 결과는 다음 shape을 가진다.

X∈Rn×dmodelX \in \mathbb{R}^{n \times d_{model}} X∈Rn×dmodel​

그림의 작은 예시처럼 seq_len = 2, d_model = 3이면 다음과 같다.

X∈R2×3X \in \mathbb{R}^{2 \times 3} X∈R2×3

Positional Encoding과 RoPE

Section titled “Positional Encoding과 RoPE”

Transformer의 self-attention은 기본적으로 토큰들을 병렬로 본다. RNN처럼 순서대로 읽지 않기 때문에, 별도의 위치 정보가 없으면 토큰 순서를 알기 어렵다.

두 문장은 같은 토큰을 포함하지만 순서가 다르므로 의미가 달라진다. 따라서 Transformer는 각 토큰에 위치 정보를 추가한다.

원래 Transformer 논문에서는 sin/cos 기반 positional encoding을 사용했다.

PE(pos,2k)=sin⁡(pos100002k/dmodel)PE_{(pos, 2k)} = \sin \left(\frac{pos}{10000^{2k / d_{model}}}\right) PE(pos,2k)​=sin(100002k/dmodel​pos​) PE(pos,2k+1)=cos⁡(pos100002k/dmodel)PE_{(pos, 2k+1)} = \cos \left(\frac{pos}{10000^{2k / d_{model}}}\right) PE(pos,2k+1)​=cos(100002k/dmodel​pos​)

최종 입력 embedding은 token embedding과 positional encoding을 더해서 만든다.

xi=ei+peix_i = e_i + pe_i xi​=ei​+pei​

예를 들어 다음과 같다.

e0=[0.5,0.7,0.2]e^0 = [0.5, 0.7, 0.2] e0=[0.5,0.7,0.2] pe0=[0,1,0]pe^0 = [0, 1, 0] pe0=[0,1,0] ie0=e0+pe0=[0.5,1.7,0.2]ie^0 = e^0 + pe^0 = [0.5, 1.7, 0.2] ie0=e0+pe0=[0.5,1.7,0.2]

요즘 GPT, LLaMA 계열 모델은 단순 sinusoidal positional encoding보다 RoPE, Rotary Positional Embedding을 많이 사용한다. RoPE는 위치 벡터를 embedding에 단순히 더하는 대신, Q와 K 벡터를 위치에 따라 회전시킨다. 목적은 동일하다.

Input Embedding Matrix

Section titled “Input Embedding Matrix”

각 토큰의 input embedding을 행으로 쌓으면 입력 행렬이 된다.

IE=[0.51.70.20.8510.740.40215]IE = \begin{bmatrix} 0.5 & 1.7 & 0.2 \\ 0.851 & 0.74 & 0.40215 \end{bmatrix} IE=[0.50.851​1.70.74​0.20.40215​]

Shape은 다음과 같다.

IE∈Rseq_len×dmodelIE \in \mathbb{R}^{seq\_len \times d_{model}} IE∈Rseq_len×dmodel​

예시에서는 다음과 같다.

IE∈R2×3IE \in \mathbb{R}^{2 \times 3} IE∈R2×3

Q, K, V 생성

Section titled “Q, K, V 생성”

Self-attention에서는 입력 X에서 Query, Key, Value를 만든다.

Q=XWQQ = XW_Q Q=XWQ​ K=XWKK = XW_K K=XWK​ V=XWVV = XW_V V=XWV​

각 projection matrix의 shape은 다음과 같다.

WQ∈Rdmodel×dkW_Q \in \mathbb{R}^{d_{model} \times d_k} WQ​∈Rdmodel​×dk​ WK∈Rdmodel×dkW_K \in \mathbb{R}^{d_{model} \times d_k} WK​∈Rdmodel​×dk​ WV∈Rdmodel×dvW_V \in \mathbb{R}^{d_{model} \times d_v} WV​∈Rdmodel​×dv​

직관적으로 보면 Q, K, V는 다음 역할을 한다.

즉 Q/K는 matching score 계산용이고, V는 실제로 전달되는 payload에 가깝다.

예를 들어 다음 shape이라면:

X∈R2×3X \in \mathbb{R}^{2 \times 3} X∈R2×3 WQ,WK,WV∈R3×3W_Q, W_K, W_V \in \mathbb{R}^{3 \times 3} WQ​,WK​,WV​∈R3×3

결과는 다음과 같다.

Q,K,V∈R2×3Q, K, V \in \mathbb{R}^{2 \times 3} Q,K,V∈R2×3

Attention score는 QK^T로 계산하므로 Q와 K의 마지막 차원은 같아야 한다.

QKT∈Rseq_len×seq_lenQK^T \in \mathbb{R}^{seq\_len \times seq\_len} QKT∈Rseq_len×seq_len

반면 d_v는 반드시 d_k와 같을 필요는 없다. V는 score 계산 대상이 아니라 weighted sum 대상이기 때문이다.

Attention Score

Section titled “Attention Score”

기본 attention score는 다음과 같이 계산한다.

Scores=QKTScores = QK^T Scores=QKT

각 원소는 다음 의미를 가진다.

scoreij=Qi⋅Kjscore_{ij} = Q_i \cdot K_j scoreij​=Qi​⋅Kj​

즉 i번째 토큰의 Query가 j번째 토큰의 Key와 얼마나 잘 맞는지를 나타낸다.

토큰이 2개인 경우 attention score 행렬은 다음처럼 볼 수 있다.

핵심은 다음과 같다.

예를 들어 score01은 다음 내적이다.

score01=Qhel⋅Kloscore_{01} = Q_{hel} \cdot K_{lo} score01​=Qhel​⋅Klo​ score01=q0k0+q1k1+q2k2score_{01} = q_0 k_0 + q_1 k_1 + q_2 k_2 score01​=q0​k0​+q1​k1​+q2​k2​

값이 클수록 Query와 Key가 잘 맞는다는 뜻이다.

Causal Mask

Section titled “Causal Mask”

Decoder 기반 LLM은 다음 토큰을 예측한다. 따라서 현재 위치에서 미래 토큰을 보면 안 된다.

예를 들어 ["_hel", "lo"]에서 첫 번째 토큰 _hel은 두 번째 토큰 lo를 보면 안 된다. 하지만 QK^T를 계산하면 _hel -> lo에 해당하는 score가 생긴다. 이 값은 정보 누설이므로 causal mask로 미래 토큰을 차단한다.

토큰 2개인 경우 mask는 다음과 같다.

Mask=[0−∞00]Mask = \begin{bmatrix} 0 & -\infty \\ 0 & 0 \end{bmatrix} Mask=[00​−∞0​]

Masked score는 다음과 같이 계산된다.

MaskedScores=QKT+MaskMaskedScores = QK^T + Mask MaskedScores=QKT+Mask [score00score01score10score11]+[0−∞00]=[score00−∞score10score11]\begin{bmatrix} score_{00} & score_{01} \\ score_{10} & score_{11} \end{bmatrix} + \begin{bmatrix} 0 & -\infty \\ 0 & 0 \end{bmatrix} = \begin{bmatrix} score_{00} & -\infty \\ score_{10} & score_{11} \end{bmatrix} [score00​score10​​score01​score11​​]+[00​−∞0​]=[score00​score10​​−∞score11​​]

Mask 값으로 0이 아니라 −∞-\infty−∞를 쓰는 이유는 softmax 때문이다.

softmax(zi)=ezi∑jezjsoftmax(z_i) = \frac{e^{z_i}}{\sum_j e^{z_j}} softmax(zi​)=∑j​ezj​ezi​​

막고 싶은 위치를 softmax 전에 −∞-\infty−∞로 만들면 다음과 같이 확률이 0이 된다.

e−∞=0e^{-\infty} = 0 e−∞=0 softmax([a,−∞])=[1,0]softmax([a, -\infty]) = [1, 0] softmax([a,−∞])=[1,0]

시퀀스 길이 5의 causal mask는 다음 패턴을 가진다.

Mask=[0−∞−∞−∞−∞00−∞−∞−∞000−∞−∞0000−∞00000]Mask = \begin{bmatrix} 0 & -\infty & -\infty & -\infty & -\infty \\ 0 & 0 & -\infty & -\infty & -\infty \\ 0 & 0 & 0 & -\infty & -\infty \\ 0 & 0 & 0 & 0 & -\infty \\ 0 & 0 & 0 & 0 & 0 \end{bmatrix} Mask=​00000​−∞0000​−∞−∞000​−∞−∞−∞00​−∞−∞−∞−∞0​​

Scaling과 Softmax

Section titled “Scaling과 Softmax”

Attention score는 바로 softmax에 넣지 않고 sqrt(d_k)로 나눈다.

ScaledScores=QKT+MaskdkScaledScores = \frac{QK^T + Mask}{\sqrt{d_k}} ScaledScores=dk​​QKT+Mask​

Q와 K의 차원이 커질수록 내적값의 크기도 커지는 경향이 있다.

Qi⋅Kj=∑m=1dkqmkmQ_i \cdot K_j = \sum_{m=1}^{d_k} q_m k_m Qi​⋅Kj​=m=1∑dk​​qm​km​

d_k가 크면 score의 분산이 커지고, softmax가 한쪽으로 과하게 쏠릴 수 있다.

softmax([20,1])≈[1,0]softmax([20, 1]) \approx [1, 0] softmax([20,1])≈[1,0]

따라서 sqrt(d_k)로 나누어 score scale을 안정화한다.

Attention probability matrix A는 다음과 같다.

A=softmax(QKT+Maskdk)A = softmax\left(\frac{QK^T + Mask}{\sqrt{d_k}}\right) A=softmax(dk​​QKT+Mask​)

각 행은 합이 1이다.

∑jAij=1\sum_j A_{ij} = 1 j∑​Aij​=1

즉 각 Query 토큰마다 어떤 Key 토큰을 얼마나 볼지에 대한 확률 분포가 된다.

Weighted Sum with V

Section titled “Weighted Sum with V”

Attention probability A를 Value matrix V에 곱한다.

O=AVO = AV O=AV

Shape은 다음과 같다.

A∈Rseq_len×seq_lenA \in \mathbb{R}^{seq\_len \times seq\_len} A∈Rseq_len×seq_len V∈Rseq_len×dvV \in \mathbb{R}^{seq\_len \times d_v} V∈Rseq_len×dv​ O∈Rseq_len×dvO \in \mathbb{R}^{seq\_len \times d_v} O∈Rseq_len×dv​

예를 들어 다음 attention probability가 있을 때:

A=[1.00.0p0p1]A = \begin{bmatrix} 1.0 & 0.0 \\ p_0 & p_1 \end{bmatrix} A=[1.0p0​​0.0p1​​]

출력은 다음과 같다.

O0=1.0⋅V0+0.0⋅V1=V0O^0 = 1.0 \cdot V^0 + 0.0 \cdot V^1 = V^0 O0=1.0⋅V0+0.0⋅V1=V0 O1=p0⋅V0+p1⋅V1O^1 = p_0 \cdot V^0 + p_1 \cdot V^1 O1=p0​⋅V0+p1​⋅V1

Attention의 본질은 다음 구조다.

수식으로 쓰면 다음과 같다.

Attention(Q,K,V)=softmax(QKT+Maskdk)VAttention(Q, K, V) = softmax\left( \frac{QK^T + Mask}{\sqrt{d_k}} \right)V Attention(Q,K,V)=softmax(dk​​QKT+Mask​)V

Multi-Head Attention

Section titled “Multi-Head Attention”

하나의 attention head는 한 가지 관점의 관계만 학습하기 쉽다. 여러 head를 두면 서로 다른 관계를 병렬로 학습할 수 있다.

이 역할은 사람이 지정하지 않고 학습 과정에서 자연스럽게 분화된다.

각 head는 독립적인 projection matrix를 가진다.

Qh=XWQhQ_h = XW_Q^h Qh​=XWQh​ Kh=XWKhK_h = XW_K^h Kh​=XWKh​ Vh=XWVhV_h = XW_V^h Vh​=XWVh​

각 head의 출력은 다음과 같다.

headh=Attention(Qh,Kh,Vh)head_h = Attention(Q_h, K_h, V_h) headh​=Attention(Qh​,Kh​,Vh​)

여러 head의 출력을 concat한다.

H=Concat(head1,head2,...,headn)H = Concat(head_1, head_2, ..., head_n) H=Concat(head1​,head2​,...,headn​)

일반적으로 다음 관계를 가진다.

head_dim=dmodelnum_headshead\_dim = \frac{d_{model}}{num\_heads} head_dim=num_headsdmodel​​ num_heads×head_dim=dmodelnum\_heads \times head\_dim = d_{model} num_heads×head_dim=dmodel​

예를 들어 d_model = 4096, num_heads = 32, head_dim = 128이면 다음과 같다.

32×128=409632 \times 128 = 4096 32×128=4096

Concat된 결과는 output projection으로 다시 섞는다.

MHA(X)=Concat(head1,...,headh)WOMHA(X) = Concat(head_1, ..., head_h)W_O MHA(X)=Concat(head1​,...,headh​)WO​ WO∈Rdmodel×dmodelW_O \in \mathbb{R}^{d_{model} \times d_{model}} WO​∈Rdmodel​×dmodel​

결과 shape은 다음과 같다.

MHA(X)∈Rseq_len×dmodelMHA(X) \in \mathbb{R}^{seq\_len \times d_{model}} MHA(X)∈Rseq_len×dmodel​

Residual Connection과 LayerNorm

Section titled “Residual Connection과 LayerNorm”

Attention output은 원래 입력을 완전히 대체하는 것이 아니라, 기존 표현에 문맥 정보를 보정값처럼 추가한다.

x1=x0+MHA(x0)x_1 = x_0 + MHA(x_0) x1​=x0​+MHA(x0​)

요즘 LLM의 Pre-LN 구조에서는 보통 다음과 같다.

x1=x0+MHA(LN(x0))x_1 = x_0 + MHA(LN(x_0)) x1​=x0​+MHA(LN(x0​))

Residual connection의 주요 목적은 기존 표현 보존, gradient 흐름 개선, 깊은 모델 학습 안정화, 필요 없는 block을 사실상 건너뛰는 효과다.

x+0≈xx + 0 \approx x x+0≈x

LayerNorm은 각 토큰 벡터 내부의 값 분포를 안정화한다.

μ=1d∑i=1dxi\mu = \frac{1}{d}\sum_{i=1}^{d} x_i μ=d1​i=1∑d​xi​ σ2=1d∑i=1d(xi−μ)2\sigma^2 = \frac{1}{d}\sum_{i=1}^{d}(x_i - \mu)^2 σ2=d1​i=1∑d​(xi​−μ)2 x^i=xi−μσ2+ϵ\hat{x}_i = \frac{x_i - \mu}{\sqrt{\sigma^2 + \epsilon}} x^i​=σ2+ϵ​xi​−μ​ LN(xi)=γx^i+βLN(x_i) = \gamma \hat{x}_i + \beta LN(xi​)=γx^i​+β

BatchNorm은 batch 전체 통계에 의존하지만, LLM inference에서는 batch size가 1일 수도 있고 sequence length도 달라진다. LayerNorm은 각 토큰 벡터 내부에서만 정규화하므로 batch 크기와 무관하게 안정적이다.

원 논문의 Transformer는 Post-LN 구조에 가깝지만, 요즘 LLM은 보통 Pre-LN 구조를 많이 쓴다.

Pre-LN은 깊은 모델에서 학습 안정성이 더 좋은 편이다.

Decoding Strategies

Section titled “Decoding Strategies”

다음 토큰을 선택하는 방식은 여러 가지가 있다.

Greedy decoding은 가장 확률이 높은 토큰을 항상 선택한다.

xt=arg⁡max⁡iP(xi∣x<t)x_t = \arg\max_i P(x_i \mid x_{\lt t}) xt​=argimax​P(xi​∣x<t​)

장점은 결정적이고 빠르며 재현 가능하다는 점이다. 단점은 반복적이고 단조로운 출력이 나올 수 있다는 점이다.

Top-k sampling은 확률이 높은 상위 k개 토큰만 남기고 그 안에서 샘플링한다.

Top-p, 또는 nucleus sampling은 누적 확률이 p 이상이 되는 최소 토큰 집합을 선택하고 그 안에서 샘플링한다.

Sp={x1,...,xm}S_p = \{x_1, ..., x_m\} Sp​={x1​,...,xm​} ∑i=1mP(xi)≥p\sum_{i=1}^{m} P(x_i) \geq p i=1∑m​P(xi​)≥p

Temperature는 softmax 전에 logits의 날카로움을 조정한다.

P(xi)=ezi/T∑jezj/TP(x_i) = \frac{e^{z_i / T}}{\sum_j e^{z_j / T}} P(xi​)=∑j​ezj​/Tezi​/T​

Beam search는 여러 후보 시퀀스를 동시에 유지하면서 가장 좋은 시퀀스를 선택한다. 번역, 요약, constrained generation 같은 구조화된 작업에서 유리할 수 있지만, open-ended chat에서는 너무 평범하거나 반복적인 결과가 나올 수 있고 계산 비용도 증가한다.

실제 LLM 서비스에서는 보통 여러 전략을 조합한다.

Greedy는 sampling을 사실상 끈 deterministic 모드에 가깝다.

KV Cache

Section titled “KV Cache”

Decode 단계에서 매번 전체 프롬프트의 K, V를 다시 계산하면 비효율적이다. 그래서 과거 토큰들의 K, V를 cache에 저장한다.

각 layer, 각 head별로 K와 V가 저장된다. 대략적인 shape은 다음과 같다.

Kcache∈Rlayers×batch×heads×seq_len×head_dimK_{cache} \in \mathbb{R}^{layers \times batch \times heads \times seq\_len \times head\_dim} Kcache​∈Rlayers×batch×heads×seq_len×head_dim Vcache∈Rlayers×batch×heads×seq_len×head_dimV_{cache} \in \mathbb{R}^{layers \times batch \times heads \times seq\_len \times head\_dim} Vcache​∈Rlayers×batch×heads×seq_len×head_dim

Decode가 진행될수록 seq_len 방향으로 cache가 증가한다.

KV cache의 장점은 과거 토큰의 K/V 재계산을 피하고 decode latency를 줄이며 긴 문맥 처리를 가능하게 한다는 점이다. 단점은 메모리 사용량이 증가하고, 긴 context에서 HBM bandwidth 병목이 커지며, batch serving에서 cache 관리가 복잡해진다는 점이다.

Serving 최적화 관점

Section titled “Serving 최적화 관점”

FlashAttention은 attention 계산의 memory access를 최적화한 fused kernel 계열 기법이다. 일반 attention은 중간 attention matrix를 HBM에 크게 저장할 수 있다.

S=QKTS = QK^T S=QKT A=softmax(S)A = softmax(S) A=softmax(S) O=AVO = AV O=AV

FlashAttention은 이를 block 단위로 계산하면서 SRAM/shared memory를 효율적으로 활용해 HBM read/write를 줄인다. Causal mask도 별도의 큰 mask 행렬을 메모리에 쓰기보다 kernel 내부에서 처리할 수 있다.

Quantization은 model weight, activation, KV cache 등을 낮은 precision으로 표현해 메모리 사용량과 bandwidth를 줄이는 기법이다.

Weight quantization은 모델 크기와 weight memory bandwidth를 줄이고, KV cache quantization은 decode 단계의 KV cache read bandwidth를 줄인다.

Paged KV Cache는 OS의 virtual memory page처럼 KV cache를 page 단위로 관리한다. 요청마다 sequence length가 다른 serving 환경에서 fragmentation을 줄이고 dynamic batching에 유리하다.

Speculative decoding은 작은 draft model이 여러 토큰 후보를 빠르게 제안하고, 큰 target model이 이를 검증하는 방식이다.

목적은 한 토큰씩 순차 생성해야 하는 decode의 체감 속도를 높이는 것이다. 다만 draft model이 필요하고, acceptance rate에 따라 효과가 달라진다.

Continuous batching은 새 요청과 진행 중인 요청을 동적으로 묶어 GPU 사용률과 throughput을 높이는 serving 기법이다.

Prefix caching은 여러 요청이 같은 system prompt나 긴 prefix를 공유할 때, 해당 prefix의 KV cache를 재사용해 prefill 비용과 첫 토큰 latency를 줄이는 기법이다.

Tensor parallelism은 큰 matrix multiplication을 여러 GPU에 shard로 나누는 방식이고, pipeline parallelism은 layer를 여러 GPU에 나누어 배치하는 방식이다. 큰 모델을 단일 GPU에 올릴 수 없을 때 필요하지만, GPU 간 통신 비용과 pipeline bubble을 고려해야 한다.
